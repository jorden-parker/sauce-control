# Comparison startup progress

Status: accepted and implemented.

## Agreed presentation

Show live named preparation steps separately for the Base Branch and Target Branch Instances, with expandable, timestamped progress messages generated by Sauce Control.

The expandable output contains controlled progress messages and safe summaries, not raw dependency-installation or development-server logs. This follows [ADR 0006](./adr/0006-deliver-comparison-credentials-through-stdin.md), including its protection against transformed credentials appearing in child output. Package installation details from command logs are unavailable under this decision.

## Agreed failure handling

If either Instance fails during preparation, show its safe failure summary immediately, stop the other Instance's preparation, and clean up both Instances and their owned preparation resources. Failure reporting must not wait for the other preparation attempt to finish.

## Agreed cancellation

Offer Cancel during Instance preparation. Cancellation stops both preparation attempts and cleans up their owned resources, using the same stopping and cleanup behavior as preparation failure.

## Agreed coverage

Live progress and Cancel cover the whole Comparison startup: Instance preparation, Page discovery, and Affected Page detection. They remain available until the Comparison is ready. Cancellation during the later stages stops that work and cleans up both Instances and their owned resources.

## Agreed browser lifecycle

Comparison startup continues when the user refreshes or leaves Compare. Returning restores the current progress, and a lost browser connection reconnects automatically. Browser disconnection does not cancel startup; explicit Cancel stops it. This does not imply that startup survives the Sauce Control process exiting.

## Agreed retention

Keep the latest startup attempt's progress available after completion, failure, or cancellation until the next Comparison starts or Sauce Control exits. Retain this progress in memory; do not add saved history.

## Agreed timing

Show elapsed time for each step and for the whole startup. Do not show a completion percentage or estimated finish time.

## Agreed steps

Show these steps independently for each Instance:

1. Clone branch.
2. Prepare container.
3. Install dependencies.
4. Start development server.
5. Wait for readiness.

Then show Comparison-wide Page discovery and Affected Page detection, followed by ready.

## Agreed delivery

Use Server-Sent Events to push progress updates to the browser as they happen. Send the current progress again on connection or reconnection. Cancel remains a separate action and does not depend on the streaming connection.

## Implementation and verification requirements

- Carry trusted progress messages from the launcher through the runtime adapter into the Comparison's progress state. Preserve suppression of raw child output throughout.
- Propagate cancellation through both Instance preparation attempts, Page discovery, and Affected Page detection. Late work must not mark a cancelled or superseded attempt ready or overwrite a newer attempt's progress.
- Show failure immediately while stopping and cleanup proceed. Do not report cleanup complete until it has completed; report a safe summary if cleanup fails.
- Verify independent Base and Target step updates, timing, expandable messages, and progress through the later startup stages.
- Verify immediate failure visibility, stopping the other attempt, cancellation during each startup stage, and cleanup of owned resources.
- Verify refresh, navigation away and back, connection loss, progress restoration, and retention after success, failure, and cancellation.
- Verify that synthetic credentials printed by child processes never reach progress messages, errors, or retained output, consistent with ADR 0006.

## Verification

The unit and integration suite passes in parallel: each smoke file owns its containers under its own app label, and images are removed by id rather than pruned, so files never conflict on Docker's single prune lock. Additional focused tests verify notification before delayed cleanup, cancellation through page analysis, and preventing a new startup during cleanup.

All 19 browser tests pass, including startup streaming, navigation and refresh, cancellation, retained progress, and retry. The rendered panel and expandable messages were inspected with no browser runtime errors.

Live Docker checks verify ordered launcher progress, credential suppression, restart delivery, and Comparison operation. Podman smoke checks remain skipped because Podman is not installed locally.
